## How this repo does UI (match it)
- **Code-first.** A screen is a thin `.tscn` (one `Control` root + script). The script
  extends `AppScreen`, overrides `build_content(root: VBoxContainer)`, and composes
  `UI.*` widgets. Do not hand-author node trees in `.tscn`.
- **Signal-driven.** Rules emit typed events; views apply them. UI never reaches back
  into `core/`.
- **Theming is data.** A theme is a `.tres` in `data/themes/` filling the `ThemeData`
  contract, listed in `data/themes/theme_ids.gd`, tiered in `core/entitlements.gd`,
  with a card bake in `assets/theme_cards/`. Colors come from `ThemeManager`; subscribe
  to `theme_changed`. Never hardcode hex.
- **Sizes go through `DesignSystem.type()` / `icon()`.** If something reads small,
  change `TYPE_GAIN` / `ICON_GAIN`, never the literal at the call site.
- **Glass everywhere.** Surfaces are `GlassPanel` (`UI.glass_card` / `UI.glass_pill`).
  Pieces are `CandyFace`. Marks are `MarkFace.draw_mark`. Type never glows.
- **Fonts.** Malam Poek (display) and Nunito (reading) from `assets/fonts/`. The Malam
  Poek file is generated by `tools/font_digits.py`; never drop the original over it.
- **Icons.** `IconLibrary` runtime SVG glass icons, or painted PNGs in `assets/icons/`.
  Functional icons tint to the theme; reward and value icons keep their own colors.
- **Motion.** `Tween` with `DesignSystem.DUR_*` and explicit easing. `CPUParticles2D`
  only, at most ~130 per emitter. Never tween rotation / scale / pivot on a Control
  that draws; tween a bare pivot parent and draw on a child. Shader `smoothstep`
  edges ascend (`1.0 - smoothstep(a, b, x)`). `ShockWave` is a moment cost, never
  per-frame.
- **Tappables.** `UI.pass_through(root)` before `UI.make_scroll_tappable(root, ...)`.
  Never layer a momentum tween over `ScrollContainer`.
- **Navigation.** `SceneRouter.goto(Route.X, payload)`; the router crossfades 0.16 s
  over the old page. Never `change_scene_to_file`. Never a fade to black.

## Conventions (hard rules)
PascalCase classes and signals · snake_case funcs/vars · UPPER_CASE consts · tabs ·
typed GDScript (`func f(x: int) -> void:`) · `class_name` is fine for `ui/` widgets and
`core/`, `preload()` elsewhere · `var x := <Variant>` is a parse error, type it
explicitly · LF line endings · copy is short and plain, no em dashes.

## Workflow
1. Restate the plan briefly. Use TodoWrite for multi-file work.
2. Implement. Keep diffs focused. Reuse widgets instead of duplicating.
3. Self-check: restyles on `theme_changed`? Root frame at or under 982 px? Touch
   targets at least 48 dp? No hardcoded colors? Reduce-motion path? Parses under
   `& "D:\Godot_v4.7.1-stable_win64_console.exe" --headless --path . --import`?
4. Update or add the tests that pin the change (`tests/`, `regression/headless/`),
   and the mutation anchor in `regression/headless/verify_tests.ps1` if you moved code
   a mutation targets. The work is not done until the suite is green.
5. Summarize files changed and **hand off to code-reviewer**, then qa-automation for
   a `/probe` still. Note anything the next agent should verify.

You may edit `.gd`, `.tscn`, `.tres`, and add assets. Board rules and AI belong to the
game-logic-engineer (`core/rules`, `core/ai`).
